# Architecture Decision Records

## 원칙
이 프로젝트의 목적은 모델 점수 경쟁이 아니라, AUC가 놓치는 확률 품질 문제를 정확히 측정하고 설명하는 것이다. 그래서 측정 방식을 먼저 고정하고, 범위는 그 이야기를 뒷받침하는 실험으로 제한한다.

---

### ADR-001: 시간순 블록 분할
**결정**: `train.txt`를 원본 행 순서대로 7개 블록으로 나눈다. 학습 1–5, 검증 6, 테스트 7.
**이유**: 실제 CTR 모델은 과거로 학습해 미래를 예측한다. 무작위 분할은 같은 시기의 패턴이 학습·평가 양쪽에 섞여 점수를 부풀리고, 시간에 따른 CTR 변화가 calibration에 주는 영향을 숨긴다.
**트레이드오프**: 무작위 분할을 쓰는 공개 벤치마크 수치와 직접 비교할 수 없다. 블록은 데이터 설명상 시간순이지만 정확한 날짜 경계는 아니다.

### ADR-002: 해싱 대신 학습 데이터 빈도 기반 vocab
**결정**: 범주형 값은 학습 블록에서 `min_count` 이상 등장한 값만 id를 주고, 나머지는 필드별 OOV로 보낸다.
**이유**: 값별 빈도가 그대로 남아 빈도 구간(head/mid/tail/OOV)별 분석에 쓸 수 있다. 해시 충돌이 결과 해석에 끼어들지 않는다.
**트레이드오프**: vocab 생성을 위해 학습 데이터를 한 번 더 읽어야 한다. 새로 등장한 값은 모두 OOV 하나로 합쳐진다.

### ADR-003: 지표 직접 구현, sklearn은 정답 비교용
**결정**: LogLoss, AUC(순위 기반, 동점은 평균 순위), ECE, NE, PCOC를 직접 구현하고 sklearn과 일치하는지 테스트한다.
**이유**: 각 지표가 무엇에 민감하고 무엇에 둔감한지 설명할 수 있어야 한다. 특히 "AUC는 단조 변환에 불변"이라는 성질을 테스트로 보여준다.
**트레이드오프**: 구현과 검증에 시간이 든다.

### ADR-004: ECE는 샘플 수가 같은 20개 구간으로 고정
**결정**: ECE 기본값은 예측값 기준으로 샘플 수가 같은 20개 구간이다. 같은 폭 구간은 보조 지표로만 보고한다.
**이유**: CTR 예측값은 한쪽에 몰려 있어서, 같은 폭 구간이면 대부분 구간이 비거나 소수 샘플로 흔들린다. 구간 방식에 따라 ECE 값이 달라지므로 결과를 보기 전에 고정한다.
**트레이드오프**: 다른 논문의 ECE 수치와 직접 비교하기 어렵다.

### ADR-005: Negative downsampling 보정은 prior correction
**결정**: negative를 비율 `w`로 남겨 학습한 모델의 예측 `p`를 `q = p / (p + (1 − p) / w)`로 보정한다. logit으로 쓰면 `logit(q) = logit(p) + log w`다.
**이유**: 샘플링 비율을 알고 있으므로 추가 학습 없이 정확한 보정식이 있다. LR에서는 bias에 `log w`를 더하는 것과 같아서 원리를 코드 한 줄로 보여줄 수 있다.
**트레이드오프**: 모델이 학습 분포에서 잘 calibrated되어 있다는 가정에 기댄다. 이 가정이 깨지면 Platt scaling 같은 사후 보정이 필요하다.

### ADR-006: LR과 DCN이 같은 데이터 파이프라인을 공유
**결정**: LR을 PyTorch의 1차원 embedding 합 + bias로 구현해 DCNv2와 데이터 로더, 학습 루프, 평가 코드를 공유한다. FTRL은 쓰지 않는다.
**이유**: 두 모델의 차이가 파이프라인 차이가 아니라 모델 구조 차이에서만 나오게 한다.
**트레이드오프**: 대규모 sparse LR의 표준 최적화 방식(FTRL)과는 다르다.

### ADR-007: 블록 Parquet 스키마와 저장 방식
**결정**: `train.txt`를 한 번 스트리밍으로 읽어 `data/blocks/block_{1..7}/part-*.parquet`(블록별 최대 100만 행 shard, zstd)로 쓴다. `label`은 Int8, `I1–I13`은 Int32, `C1–C26`은 32비트 16진수 해시를 UInt32로 바꿔 저장한다. 빈 칸은 모두 null로 남기고, 결측 처리는 이후 전처리 단계에서 정한다. 블록 경계와 블록별 행 수·양성 수는 `manifest.json`에 기록한다.
**이유**: 16진수 문자열보다 UInt32가 작고 비교·join이 빠르며, 값 자체는 손실 없이 보존된다. 정수 변환은 strict로 해서 범위를 넘는 값이 있으면 조용히 잘리지 않고 실패한다. 블록 경계는 `k·N // 7`로 정해 블록 크기 차이가 최대 1행이다.
**트레이드오프**: 원본 16진수 표기가 필요하면 다시 포맷해야 한다. 결측을 null로만 두었으므로 vocab·정규화 단계에서 결측 토큰과 결측 구간을 명시적으로 만들어야 한다.

### ADR-008: 지표 세부 정의 고정
**결정**: 실제 데이터 결과를 보기 전에 `src/ctr/metrics.py`의 세부 정의를 다음과 같이 고정한다.
- **NE 분모**: 학습 블록(1–5) CTR을 모든 행에 예측했을 때의 LogLoss다. `ne()`의 `base_rate`는 기본값 없는 필수 인자다. 평가 split 자신의 CTR(entropy)은 쓰지 않는다.
- **LogLoss clip**: `p`를 `[1e-15, 1 − 1e-15]`로 자른다. 계산은 입력 dtype과 상관없이 float64로 한다.
- **ECE 동점 처리**: 안정 정렬 후 크기 차이가 최대 1인 20개 위치 구간을 만들되, 같은 예측값을 가진 행 묶음은 쪼개지 않고 그 묶음의 가운데 행이 속한 구간에 통째로 넣는다. 빈 구간은 버린다.
**이유**: NE 분모를 학습 CTR로 두면 He et al. (2014)의 background CTR 정의와 같고, 평가 라벨로 분모를 만드는 일이 없다. 상수 기준선(`reports/baseline_constant.json`)은 정의상 NE = 1이 된다. ECE에서 동점 묶음을 위치대로 자르면 결과가 동점 행들의 원래 순서에 좌우되는데, 이 데이터에서 행 순서는 시간 순서다. 실제로 상수 예측의 ECE가 `|p − ctr|`이 아니라 라벨 순서에 따라 0.4까지 나오는 것을 테스트에서 확인했다. 가운데 행 기준은 AUC가 동점에 평균 순위를 주는 것과 같은 대칭성을 가진다.
**트레이드오프**: 동점이 많으면 구간 크기가 같지 않고 구간 수가 20보다 적어질 수 있다. 동점이 없으면 `np.array_split`과 같은 구간이 된다.

### ADR-009: 피처 전처리와 vocab id 배치
**결정**: 39개 필드를 모두 범주형 id로 바꾼다.
- **수치 피처 I1–I13**: `x ≤ 2`(음수 포함)는 값 그대로, `x > 2`는 `floor(ln(x)²) + 3`으로 구간화한 정수 토큰을 쓴다. `+3`은 구간 토큰이 그대로 둔 작은 값(−3…2)과 겹치지 않게 한다.
- **vocab**: 학습 블록(1–5)에서 필드별로 `min_count = 10`번 이상 나온 토큰만 남긴다. 필드마다 id 0은 결측(null), 1은 OOV(학습에서 10번 미만이거나 처음 보는 값), 2부터는 학습 빈도 내림차순(동률은 값 오름차순)이다.
- 결과는 `data/encoded/`에 블록 Parquet과 같은 shard 구성의 Int32 id로 저장하고, vocab(값·빈도)과 필드별 결측·OOV 행 수를 `data/encoded/vocab/`에 남긴다.
**이유**: 구간화는 통계가 필요 없어 누수 여지가 없고, 수치 피처도 같은 embedding 경로를 타므로 LR이 "1차원 embedding 합 + bias"로 끝난다(ADR-006). `floor(ln(x)²)` 구간화와 `min_count = 10`은 Criteo 공개 벤치마크(BARS/FuxiCTR의 Criteo 전처리)에서 쓰는 설정과 같아 수치를 비교할 기준이 생긴다. 결측을 OOV와 다른 id로 두면 "값이 없음"과 "드문 값"을 모델이 따로 학습한다. 남긴 빈도는 6단계의 빈도 구간 분석에 그대로 쓴다.
**트레이드오프**: 구간 안의 크기 차이는 버려진다. 수치 피처를 정규화한 연속값으로 넣는 방식과 직접 비교하지 않는다. 학습에서 10번 미만인 값도 OOV로 보내므로, OOV id는 "학습에서 드물었던 값"과 "새로 등장한 값"을 구분하지 않는다.

### ADR-010: 학습 절차
**결정**: 학습 블록 안에서는 행을 섞는다. epoch마다 shard 순서를 무작위로 바꾸고, shard 5개(약 500만 행)씩 읽어 그 안에서 행을 섞어 배치를 만든다. 최적화는 Adam, 배치 4096, 손실은 BCE이고, 모든 weight는 0, bias는 `logit(학습 블록 CTR)`에서 시작한다. 매 epoch 끝에 검증 블록(6) 전체로 평가해 LogLoss가 가장 낮은 epoch을 남기고, `patience` epoch 동안 나아지지 않으면 멈춘다. 학습률 같은 설정은 학습 블록 앞쪽 shard와 검증 블록 일부로 고른다. 테스트 블록(7)은 남긴 epoch으로 한 번만 평가한다.
**이유**: 블록 분할(ADR-001)이 시간 경계를 지키므로, 섞는 범위를 학습 블록 안으로 제한하면 검증·테스트로 미래 정보가 새지 않는다. 학습 블록을 시간순 그대로 흘리면 배치마다 같은 시기의 행만 모여 기울기가 치우치고, 마지막 shard의 분포에 가장 많이 맞춰진다. 초기 모델이 상수 CTR 기준선과 같아서 NE = 1에서 출발한다.
**트레이드오프**: shard 묶음 단위 셔플이라 전체 무작위 셔플보다 배치 간 상관이 남는다. 학습 블록 안의 시간 변화(최근 행에 더 맞추는 효과)는 이용하지 않는다. MPS 연산은 실행마다 비트 단위로 같다고 보장되지 않아, seed 고정은 CPU에서만 결과를 완전히 재현한다.
